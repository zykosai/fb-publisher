# Публикация проекта на GitHub

Имя проекта: **FB Publisher**. Рекомендуемое имя репозитория: `fb-publisher`.

## Что подготовлено

- MIT, README на английском и русском, правила вкладов и безопасности.
- Первый запуск Windows с автоматической установкой зависимостей.
- Автоматические проверки GitHub Actions без настоящих входов в Facebook.
- Игнорирование всей папки `data/`, `.env`, браузерных профилей, архивов и диагностик.
- Сборщик чистого исходного ZIP и проверка на случайно попавшие секреты.

## Размещение

1. Создай пустой репозиторий `fb-publisher` в своём аккаунте GitHub. Не создавай там второй README или LICENSE: они уже есть в проекте.
2. Из папки проекта выполни проверку: `.\.venv\Scripts\python.exe scripts\check_distribution.py --git`.
3. Проверь `git status` и список файлов `git ls-files`. Там не должно быть `data/`, `.env`, фото и cookies.
4. Сделай первый commit под своим именем и привяжи репозиторий:

```powershell
git add .
git commit -m "Prepare FB Publisher for open source"
git remote add origin https://github.com/YOUR_USERNAME/fb-publisher.git
git push -u origin main
```

Замени `YOUR_USERNAME` на свой логин. Если Git просит имя и email, настрой свою
личность самостоятельно; можно использовать приватный noreply-email GitHub.
Токены и пароли не вставляй в исходники или команды с URL репозитория.

Если Git пишет `dubious ownership`, не отключай защиту для всех папок. Проще
распаковать чистый ZIP в новую папку, созданную под твоей учётной записью, и
инициализировать Git там. Настройки доверенных каталогов этой подготовкой
глобально не меняются.

## Скачивание для пользователей

Создай Release вручную после успешного CI и прикрепи чистый архив из `dist/` вместе
с `.sha256`. Это исходный проект, не самостоятельный EXE: пользователю всё ещё
нужен Python и интернет при первой установке. Для запуска после распаковки —
двойной клик по `PC START.cmd`.

Никогда не архивируй всю свою рабочую папку через «Отправить → ZIP»: даже при
правильном `.gitignore` обычный архиватор включит приватные данные. Используй
`scripts/build_release.py`, который выбирает только разрешённые исходники.

## После публикации

Добавь описание репозитория, темы `facebook`, `python`, `playwright`, `self-hosted`
и включи Issues. При необходимости включи private vulnerability reporting.
Публикация на GitHub, создание удалённого репозитория и push требуют отдельного
действия владельца; подготовка локальных файлов сама по себе ничего не загружает.
